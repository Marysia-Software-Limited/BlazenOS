# Agent rules — `ios/`

Cross-agent rules for the iOS implementation. Defers to the
monorepo-level [`/AGENTS.md`](../AGENTS.md) and [`/CLAUDE.md`](../CLAUDE.md)
for anything not stated here.

## 1. Invariants (do not violate)

1. **Native Apple APIs only for ML.** No Flutter, no React Native.
   `Speech`, `AVSpeechSynthesizer`, `SoundAnalysis`, Foundation Models,
   App Intents, Live Activities — called from Swift directly. Rust owns
   cross-platform logic; the OS owns ML and UI.
2. **PL+EN parity.** Every user-facing string lives in `L10n.swift`
   with both keys populated. A change that adds only the English copy
   is incomplete. (Once the string catalogue migration lands, the
   `.xcstrings` file replaces `L10n.swift` — the parity rule still
   applies.)
3. **Shared core stays Rust.** Intent routing, sync log, adapter
   contracts → `crates/jessica-core/`. The Swift placeholder in
   `JessicaCore` exists for M0 only.
4. **FFI signatures are the contract.** Swift code that touches the FFI
   matches the cbindgen-generated `jessica_ffi.h`. If you change one
   side, regenerate the other in the same commit.
5. **iOS 17.0 minimum.** No version drift without a product-decision
   doc entry. Foundation Models work happens behind an
   `if #available(iOS 18.4, *)` guard.
6. **Voice-first sanity check.** The user has no screen for daily use.
   Any feature is incomplete if it can't be reached, discovered, and
   recovered from by voice.

## 2. Where things go

| File you want to change       | Lives in                              |
|-------------------------------|---------------------------------------|
| App UI                        | `Jessica/Views/`                      |
| `@main` entry / app lifecycle | `Jessica/App/JessicaApp.swift`        |
| Strings (PL + EN)             | `Jessica/Resources/L10n.swift`        |
| App resources                 | `Jessica/Resources/`                  |
| Voice plugin Swift code       | `Jessica/Voice/`                      |
| Swift public API surface      | `JessicaCore/Sources/JessicaCore/`    |
| FFI seam                      | `JessicaCore/Sources/JessicaCore/JessicaFFI.swift` |
| Unit tests (pure Swift)       | `JessicaCore/Tests/JessicaCoreTests/` |
| App integration tests         | `JessicaTests/`                       |
| Per-project docs              | `docs/`                               |

Anything in `crates/`, `configs/`, `rpi5/src/blazend/`, `docs/product/`
belongs to the broader monorepo — do not edit from this project.

## 3. Maintenance loop ("let do maintenance")

1. `make test` — `JessicaCoreTests` via `swift test` (no Xcode UI)
2. `make build` — `xcodebuild` for the simulator
3. If you touched `JessicaCore`'s FFI seam: `cargo test -p jessica-core -p jessica-ffi` from the repo root.
4. Update `docs/` to match behaviour changes.
5. Update `L10n.swift` PL+EN keys together — never one without the other.

## 4. What not to commit

- `Jessica.xcodeproj/` (generated by XcodeGen; regen via `make project`)
- `build/`, `DerivedData/`, `.build/`
- `*.xcuserstate`, `xcuserdata/`
- Signing material (`*.p12`, `*.mobileprovision`, App Store Connect API keys)
